## 2. Мета роботи
Замінити основні циклові обчислення в наявній предметній моделі готелю на декларативні запити Stream API без зміни зовнішньої поведінки програми та збереженням усіх попередніх показників звіту (`validCount`, `totalNights`, `maxNights`, загальний виторг, кількість унікальних кімнат)[cite: 9, 12].

## 3. Стан до і після цієї роботи
* **До:** У `BookingController.generateReport()` обчислення загального виторгу та формування підсумків відбувалося вручну всередині циклу `for` із накопичувальними змінними.
* **Після:** Основні запити винесено в окремий утилітний клас `BookingQueries` як чисті функції над потоками (`Stream API`). Відновлено вивід усіх попередніх показників статистики (`validCount`, `totalNights`, `maxNights`).

## 4. Контракт даних
* **Базовий поліморфний тип:** абстрактний клас `Booking` із незмінними (`final`) полями `room` (номер кімнати), `guestName` (ім'я гостя), `nights` (кількість ночей) та `kind` (категорія номера `RoomKind`)[cite: 23].
* **Підтипи:** `StandardBooking` (стандартний тариф) та `PremiumBooking` (преміум-надбавка 20% у поліморфному методі `getCost()`).
* **Enum:** `RoomKind` (`STANDARD`, `PREMIUM`) із текстовими мітками `label()`.
* **Правила валідності:** `room > 0`, `nights >= 0`, `guestName` не порожній, `kind != null` (перевіряються статичними валідаторами до виклику приватного конструктора для запобігання `CT_CONSTRUCTOR_THROW`).

## 5. П'ять запитів Stream API
1. **Відбір (`filterByMinNights`)**: джерело `bookings.stream()` → проміжна операція `.filter(b -> b.getNights() >= minNights)` → кінцева `.toList()` (результат: `List<Booking>`)[cite: 13, 14].
2. **Перетворення (`extractRoomNumbers`)**: джерело `bookings.stream()` → `.map(Booking::getRoom)` → `.toList()` (результат: `List<Integer>`)[cite: 13, 14].
3. **Групування (`countByKind`)**: джерело `bookings.stream()` → `.collect(Collectors.groupingBy(Booking::getKind, () -> new EnumMap<>(RoomKind.class), Collectors.counting()))` (результат: `Map<RoomKind, Long>`).
4. **Статистика (`nightsStatistics`)**: джерело `bookings.stream()` → `.collect(Collectors.summarizingInt(Booking::getNights))` (результат: `IntSummaryStatistics`).
5. **Top-N (`topLongestBookings`)**: джерело `bookings.stream()` → `.sorted(byNightsDescThenRoomAsc)` → `.limit(limit)` → `.toList()` (результат: `List<Booking>`)[cite: 14, 17].

## 6. Групування та статистика
* **Групування:** ключем є `RoomKind`, типом карти обрано `EnumMap<RoomKind, Long>` для стабільного природного порядку переліку. Агрегат — `Collectors.counting()`.
* **Статистика:** `IntSummaryStatistics` повертає `count`, `sum`, `min`, `max` та `average` за тривалістю проживання (`nights`).
* **Порожній вхід та форматування:** для порожнього потоку `count == 0`, `sum == 0`, а `maxNights` у звіті явно обробляється як `0` замість `Integer.MIN_VALUE`. Усі дробові значення форматуються з `Locale.ROOT`[cite: 16].


## 7. Optional
* **Ключ пошуку:** номер кімнати (`int room`) у методі `findByRoom(List<Booking> bookings, int room)`.
* **Знайдений результат:** `.filter(b -> b.getRoom() == room).findFirst()` повертає `Optional.of(booking)` (перший запис у початковому порядку при дублюванні ключа).
* **Відсутній результат:** повертає `Optional.empty()` замість `null`, що перевіряється через `isEmpty()` та безпечно обробляється через `orElse(...)` або `orElseThrow(...)`.

## 8. Еквівалентність («цикл → Stream API → результат»)

| Задача | Циклова реалізація | Stream API реалізація | Результат на контрольному наборі (6 записів) |
| :--- | :--- | :--- | :--- |
| Відбір (`nights >= 3`) | `for` + `if (b.getNights() >= 3)` + `list.add(b)` | `.filter(b -> b.getNights() >= 3).toList()` | 5 записів (включно з межею `3`) |
| Номери кімнат | `for` + `rooms.add(b.getRoom())` | `.map(Booking::getRoom).toList()` | `[105, 202, 101, 304, 102, 105]` |
| Кількість за тарифом | `Map` + `map.put(k, map.getOrDefault(...) + 1)` | `groupingBy(Booking::getKind, EnumMap, counting())` | `{STANDARD=4, PREMIUM=2}` |
| Статистика ночей | Ручні лічильники `count`, `sum`, `max` | `collect(summarizingInt(Booking::getNights))` | `count=6, sum=25, min=1, max=7, avg=4.17` |
| Загальний виторг | `total += b.getCost()` у циклі | `mapToDouble(Booking::getCost).sum()` | Сума збігається до 4-го знаку (`0.0001`) |
| Top-5 бронювань | Копіювання списку + `list.sort(...)` + цикл до 5 | `.sorted(byNightsDescThenRoomAsc).limit(5).toList()` | Кімнати `[202, 101, 304, 105, 105]` |
| Пошук за кімнатою | `for` + `if (b.getRoom() == room) return b; return null;` | `.filter(b -> b.getRoom() == room).findFirst()` | `Optional[Олег]` для `105`; `Optional.empty` для `999` |

## 14. Відповіді на контрольні питання
1. **Чим потік відрізняється від колекції?** Колекція — це структура даних у пам'яті, що зберігає елементи, тоді як потік (`Stream`) не зберігає дані, а описує конвеєр обчислень над джерелом і є одноразовим.
2. **Які частини має типовий конвеєр Stream API?** Джерело (`source`), нуль або більше лінивих проміжних операцій (`intermediate operations`) та одну кінцеву операцію (`terminal operation`), яка запускає обчислення.
3. **Чому проміжні операції називають лінивими?** Вони не виконуються в момент виклику, а лише формують план перетворень і починають обробляти елементи тільки після виклику кінцевої операції.
5. **Чим `map` відрізняється від `mapToDouble`?** `map` повертає об'єктний потік `Stream<R>` (що потребує автопакування для чисел), а `mapToDouble` повертає спеціалізований примітивний потік `DoubleStream` із готовими методами агрегації (`sum()`, `average()`).
7. **Чому порядок `sorted().limit(N)` відрізняється від `limit(N).sorted()`?** `sorted().limit(N)` спочатку впорядковує всю колекцію і бере `N` найкращих елементів, тоді як `limit(N).sorted()` обрізає перші `N` елементів у початковому порядку і сортує лише їх.
11. **Як отримати суму в кожній групі через downstream collector?** Передати другим (або третім) аргументом у `Collectors.groupingBy` колектор `Collectors.summingInt(...)` або `Collectors.summingDouble(...)`.
15. **Чому `reversed()` потрібно застосовувати до окремого ключа до `thenComparing`?** Бо виклик `reversed()` після `thenComparing()` інвертує напрямок усіх попередніх критеріїв сортування, а не лише першого.
16. **Яку проблему розв'язує `Optional` у методі пошуку?** Він явно сигналізує викликаючому коду, що результат може бути відсутнім, усуваючи ризик виникнення `NullPointerException` при поверненні `null`.
